# 直播预言 1.1.2：定位、稳定性与选项布局

按用户反馈修正 1.1.1。请将本地 `bilibili-live-prophecy.user.js` 全文替换到 Tampermonkey 并保存，刷新整个直播间；图标提示版本应为 `v1.1.2`。只启用一份脚本，本地版本未发布远程。

## 修改

- 默认宽度恢复为 **420px**，右边缘对齐弹幕区，底部贴在工具栏上方；不再把内容强行压成弹幕区宽度。视口不足时才缩小。
- 持久宿主放在与原生弹层相同的定位容器中，使用 `position:absolute; bottom:100%; right:0`。沿用原生 Vue `setting-dialog` 的悬停和关闭方法，但不再把它动画中的 `getBoundingClientRect()` 坐标复制到另一个 fixed 面板。
- 移除布局对原生 Vue `currentContent.width/height` 的反馈写入。原生控制器的空内容槽只处理生命周期，并以专属 CSS 隐藏；不再反复改写原生节点的透明度、位置或尺寸，也不会因它的缩放动画移动真实面板。
- 空闲检查只在值变化时更新宿主样式、导航属性和提示文字。避免相同值的重复 DOM 修改继续触发页面或扩展的布局观察。
- iframe 文档通过跨脚本环境可比较的字符串标识判断，避免同一个 Document 的不同包装对象导致重复初始化或取消确认；已增加对应回归测试。
- 普通打开/关闭与全屏切换都保留 iframe。进入全屏且原定位容器不在全屏元素内时才使用顶层 popover；退出后恢复相对定位。过滤全屏布局变化引起的非用户鼠标移出，后续关闭仍委托原生方法。
- 重置 1.1.1 坐标缓存。用户主动拖动后保留自由放置与会话位置。
- 竞猜选项减少左右内边距，参与反馈保持一行；短答案选项的基础高度统一为 **76px**。保留官方文字、选项、状态和请求，不改写参与规则。

## 复现和验证

之前的受控原生组件测试没有覆盖 CSS 缩放。补上 `zoom:1.25` 后，旧实现可复现原生锚点 x=1000、面板 x=1250 的错误；视口坐标再次被 CSS 缩放。这个复现解释了一类错位，不能据此断言用户浏览器具体使用了哪一种缩放或扩展。

当前默认原生组件测试包含真正的公开原生 JS/CSS、原生动画和四种布局：正常、1.25 倍 CSS 缩放、1.5 倍 CSS 缩放，以及 1.25 倍缩放叠加祖先 transform。各场景检查：

- 面板右缘与弹幕区右缘对齐，底缘与工具栏上缘对齐；默认保持 420 CSS px。
- 连续 60 帧中，面板和播放器位置没有跳动，面板没有重复隐藏；空闲宿主及其 Shadow DOM 的修改记录为 0。
- 从图标移入面板、再移入 iframe 可以继续操作；取消确认及切换原生设置正常。
- 关闭重开及进入/退出全屏时，iframe 实例保持相同。

官方 H5 使用真实 Vue 卡片和模拟接口检查“等待结算 / 预言成功得1硬币”。在 **420、360、320、280px** 四种 iframe 宽度下，反馈均为一行且完整放在按钮内，两侧按钮高度都是 **76px**，没有被文字撑长。模拟 API 的参与请求未发送到 B 站。
